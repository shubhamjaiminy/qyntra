# Qyntra live demo — 10 minutes

The story: **point Qyntra at one feature, and it tells you whether it is
ready — and catches the bug a developer just introduced.** Everything
runs on your laptop against Acme Shop, a small demo app with bugs you
can switch on during the call.

## Before the call (5 minutes)

```bash
npm run demo:reset          # healthy mode, clean history
npm run demo:app            # terminal 1: Acme Shop on http://localhost:4173 — leave running
```

In terminal 2, run the full AI version once, so its report is ready to
show (it takes several minutes with a local model):

```bash
npm run demo:feature        # writes demo/qyntra-out/features/discount-rules/report.md
cp demo/qyntra-out/features/discount-rules/report.md /tmp/ai-report.md
```

Open http://localhost:4173/admin/discount-rules in a browser tab, and
`/tmp/ai-report.md` in an editor tab.

During the call, use `--no-ai`: about 30 seconds a run, so nobody waits.

## Act 1 — "Is this feature ready?" (2 min)

Show the Discount Rules page in the browser: a table, search, a status
filter, an Add Rule form. *"A typical back-office feature. Normally
someone clicks through this before every release."*

```bash
npm run demo:feature -- --no-ai
```

Point out, as it runs:

- It **found the feature by name** in the menu — no URL, no selectors.
- It is **read-only**: write requests are blocked at the network, so it
  is safe on a shared staging environment.
- **Verdict: READY**, with four behaviour tests that passed: search
  narrows the list, the filter filters, an empty form is rejected, a
  150% discount is rejected.

*"Those aren't 'the search box exists' tests. Each one checks a rule
any application must follow — and the tests are generated by code, so
an AI can't water them down into passing."*

## Act 2 — "A developer breaks search" (2 min)

```bash
npm run demo:mode -- search-bug
npm run demo:feature -- --no-ai
```

- **Verdict: NOT READY**, exit code `1` — in CI, the pull request is
  blocked.
- Open the report: *"Search for 'Summer' shows only matching rows —
  searched for 'Summer': fewer rows should remain, all containing it,
  but it did not."*
- The failing test is a normal Playwright file in
  `demo/qyntra-out/features/discount-rules/suite/` — the team keeps it.

## Act 3 — "The bug that costs money" (2 min)

```bash
npm run demo:mode -- validation-bug
npm run demo:feature -- --no-ai
```

*"Someone removed a range check. Now a 150% discount saves."* Qyntra:
**NOT READY** — *"'Discount (%)' rejects 150 … but it did not."* No one
wrote that test; Qyntra knew a percentage above 100 is never valid.

Optionally `filter-bug` too: the Active filter shows inactive rules.

## Act 4 — "It understood the feature" (2 min)

Show `/tmp/ai-report.md`, from the AI run before the call:

- **What the feature is for** and **How to use it**, step by step —
  written by Qyntra from the screens.
- **Drawbacks**, split into *observed in the browser* (facts) and *AI
  review* (labelled "verify before acting").
- *"Only facts and failing tests can make a feature not ready. The AI's
  opinion never decides the verdict."*

## Close (1 min)

```bash
npm run demo:mode -- healthy
```

- Runs in **your** CI. Your code and data never leave it; the AI can be
  a free model on your own machine.
- *"Would you try it on one feature of your staging app for four weeks?"*
  → `docs/pilot/ONBOARDING.md`.

## If something goes wrong

| Symptom | Fix |
| --- | --- |
| "could not be found in the application's menu" | `npm run demo:app` is not running, or is on another port |
| Verdict READY in a bug mode | `npm run demo:mode -- <mode>` was run in the wrong folder; check `demo/.demo-mode` |
| AI run is slow | Expected with a 7B local model; use the report prepared before the call |

## The benchmark behind the demo

`npm run demo:benchmark` runs all four modes and scores them: healthy
must not be *not ready*, and each bug mode must be *not ready* because
a test failed. With `QYNTRA_AI_PROVIDER=none` it takes about 3 minutes;
on 2026-10-12 it scored 4 of 4, each bug caught by exactly the probe
for it.
